RFI-IRFOS · Ternary Intelligence Stack

The world isn't
binary.

A programming language, compiler, and virtual machine built on three states: −1 reject, 0 hold, +1 affirm. When evidence is insufficient, the program says so — instead of guessing.

Why Three States

You already think in three states.

Every AI system that forced a yes/no answer when evidence wasn't there has made a wrong call. That is a design flaw, not a model flaw.

The root cause of AI hallucination: Binary systems must produce an output — even when they don't have enough information. Ternlang adds a third return value: trit = 0, meaning "not enough evidence to commit." The system stops and says so, instead of making up an answer. This is a compile-time enforcement, not a prompt instruction.

Engineering

A traffic light with two states causes accidents.

Yellow is not an error — it is the correct output for a system mid-transition. Most distributed system failures happen during state transitions that binary logic has no way to represent cleanly.

In practice: The BET VM instruction THOLD suspends the program counter and gates the ALU clock while a state is volatile. This is a deterministic mutex with no speculative branch — the CPU simply does not execute the conflicting instruction.
Medicine

Clinical hold is a protocol, not a failure.

"Order more tests" is a valid clinical answer. Binary AI has no type for it — it must pick a diagnosis or refuse. trit = 0 is a typed escalation signal that routes to a human or secondary pass, instead of fabricating a result.

In practice: The MoE-13 Safety gate returns trit = 0 when confidence falls below the commit threshold. The calling system receives a typed "insufficient evidence" response and routes to a human escalation handler or secondary inference pass — instead of fabricating an answer.
Law

"Insufficient evidence" is a verdict.

A dismissed case is a valid outcome — not a system error. Standard AI has no data type for this. Ternlang's trit type gives ambiguity a concrete numerical value that propagates through the call stack. The compiler forces you to handle it.

In practice: trit is a 2-bit type: {−1, 0, +1}. It is not a float, not a nullable bool. The compiler enforces exhaustive 3-way match — if your code doesn't handle the zero case, it does not compile. Uncertainty becomes a handled code path.

TernAudit.

Every AI decision: traceable, timestamped, explainable — before and after it happens.

TernAudit logs every trit=0 hold and trit=−1 veto with a full trace: which expert voted, at what confidence, on which input, and why. No silent overrides. Permanent log to AxisMemory. This is the audit trail the EU AI Act (Articles 13, 14, 15) requires — built in, not bolted on.

Evidence Graph

See exactly which input dimensions pushed — or failed to push — your agent's confidence above threshold. Real-time, during inference. Not a post-mortem. You watch the decision form.

Veto Trace

Safety fired a −1 block. TernAudit gives you the expert name, its confidence score, and the exact input vector that triggered it — timestamped, permanently logged to AxisMemory. You don't debug it. You read it.

Resolution Path

Agent stuck on trit=0? TernAudit generates a typed evidence request: the exact dimensions that are under-threshold and what value they need to resolve. You supply the data. The hold clears. No guesswork, no manual log trawl.

Your Memory Stack Just Said No.

Binary AI treats all memory as equal weight — a new instruction can silently overwrite a safety rule. Ternlang structures memory in three layers: L1 is hot working context (ephemeral), L2 holds ternary-compressed session patterns, L3 is immutable identity anchors that cannot be overridden. When L1 tries to promote something that contradicts an L3 veto, the system says no — loudly, traceably, never silently.

Lab 03

It Doesn't Guess. It Waits.

Binary inference must return an answer on every call — even when the evidence isn't there yet. The deliberation engine fixes this: it accumulates confidence across multiple rounds using an exponential moving average, and only commits once it crosses a threshold. Below that threshold it returns trit=0 — "I need more data." That's not a failure state. That's the correct machine output under uncertainty.

Pick a scenario. Press Deliberate. Watch confidence accumulate round by round via S_r = 0.3·e + 0.7·S_{prev}. It only commits to +1 or −1 when confident enough. Until then: trit=0. Waiting is the correct answer.

Lab 04

Zero Means Don't Bother.

Neural networks burn most of their power on matrix multiplications — billions of weight × activation multiplies per inference pass. In ternary BitNet, every weight is constrained to {−1, 0, +1}. A weight of zero requires no multiply at all: the BET VM skips it at the instruction level, no branch needed, no masking overhead. BitNet b1.58 puts roughly 60% of weights here by design. This is where the 60% power reduction comes from.

Click any +1 or −1 weight to prune it to zero. Every zero is a multiply-accumulate the BET VM skips entirely — no branch, no masking, just gone. Watch active compute and power consumption drop in real time as you prune.

Lab 06

Three States. Nine Outcomes.

Every logic operation you know assumes two states: true or false. Adding a third state — unknown, withheld, uncertain — changes the entire truth table. The OR analog doesn't just return true or false anymore; it has to decide what to do when one input is uncertain. So does AND. So does addition. Ternary arithmetic has consistent, non-arbitrary rules for all of it.
